# ttblow

Telegram-бот для TikTok и Instagram Reels в режиме Guest Mode: бот скачивает видео, а TikTok-фотоподборки отдаёт rich-сообщением — каруселью оригинальных фото с треком TikTok, загружает файлы в закрытый Telegram-канал, а в чат отвечает guest-сообщением.

## Как это работает

```text
@бот <ссылка> в любом чате → guest-запрос
        ↓
плейсхолдер «⏳ Загрузка...» → TikTok → yt-dlp + proxy → /tmp → закрытый канал
                                                                    ↓
                                                                file_id
                                                                    ↓
                                             подмена плейсхолдера на видео
```

Есть и второй путь — через инлайн-результат: наберите `@бот <ссылка>`, тапните «Скачать видео», и в чат уйдёт `@бот 🦊🐼🌵🦉🍄` — пять случайных эмодзи, на которых висит скрытая ссылка (`text_link`), без превью. Guest-флоу подхватывает это упоминание и отвечает как обычно. Пул эмодзи — `src/ttblow/bot/emojis.txt`, по одному на строку.

Кэш состоит из двух уровней:

- `cachetools.TTLCache` — быстрый кэш в RAM;
- `diskcache` — локальный кэш на диске, переживающий перезапуск.

В кэше хранятся только platform ID и Telegram `file_id`. Видео хранится у Telegram.

## Настройка

1. В `@BotFather` откройте настройки бота (MiniApp) и включите **Guest Mode** — иначе бот не будет получать упоминания.
2. Командой `/setinline` включите инлайн-режим — он даёт результат, который прячет ссылку за эмодзи. Без него работает обычный флоу `@бот <ссылка>`.
3. Создайте закрытый канал и добавьте бота администратором с правом публикации.
4. Создайте `.env`:

```env
TELEGRAM_BOT_TOKEN=токен_от_BotFather
YTDLP_PROXY=http://proxy.example:8080
TELEGRAM_PROXY=http://proxy.example:8080
TELEGRAM_CACHE_CHAT_ID=-1001234567890
```

Для публичного канала вместо числового ID можно использовать его username:

```env
TELEGRAM_CACHE_CHAT_ID=@my_cache_channel
```

Proxy для `yt-dlp` и Telegram API опционален. Если `TELEGRAM_PROXY` не указан, для Bot API используется `YTDLP_PROXY`; если оба пустые, запросы идут напрямую.

По умолчанию одновременно обрабатываются 2 загрузки, максимальный размер видео — 50 MB, длительность — 600 секунд, лимит пользователя — 10 запросов в минуту. Эти значения настраиваются через `MAX_CONCURRENT_JOBS`, `MAX_FILE_SIZE`, `MAX_DURATION`, `RATE_LIMIT_COUNT` и `RATE_LIMIT_WINDOW`.

## Запуск

Скопируйте пример конфигурации и заполните `.env`:

```bash
cp .env.example .env
```

Для production через Docker и polling:

```bash
./start.sh
```

Скрипт собирает Alpine-образ, удаляет старый контейнер, запускает новый с `restart unless-stopped` и сохраняет `diskcache` в Docker volume `ttblow-cache`.

Логи:

```bash
docker logs -f ttblow
```

Для ручного запуска без Docker нужен установленный `ffmpeg` в `PATH`:

```bash
uv run python -m ttblow.main
```

Проверки кода:

```bash
uv sync --extra dev
uv run ruff format --check src tests
uv run ruff check src tests
uv run pytest -q
uv run coverage run --source=ttblow -m pytest -q && uv run coverage report -m
```

Production запускается через polling.

В Telegram:

```text
@имя_бота https://vm.tiktok.com/ZN8dRB5uV/
@имя_бота https://www.instagram.com/reel/ABC123/
```

Упоминание нужно выбрать из подсказки клиента — по нему Telegram вызывает бота в этом чате. Бот ответит в том же чате, даже если не состоит в нём: работают приватные чаты, группы и супергруппы, кроме секретных чатов и групп с защитой контента. Один ответ на одно упоминание, поэтому сначала приходит «⏳ Загрузка...», а потом это же сообщение подменяется видео.

В личном чате с ботом можно просто отправлять ссылки сообщением, а `/start` покажет справку.

## Администрирование

Укажите `ADMIN_CHAT_ID` в `.env` — владелец бота получит две команды (все остальные получают отказ):

- `/clear-cache` — сбрасывает RAM и диск кэш; видео будут скачаны и залиты заново;
- отправка файла с именем `cookie.txt` — обновляет cookies в контейнере без рестарта: файл сохраняется (или перезаписывается) в `/data/cache/cookies.txt` — тот же volume, что и кэш, поэтому отдельный bind mount не нужен. Это значение по умолчанию; `YTDLP_COOKIES_FILE` в `.env` позволяет указать другой путь.

Поддерживаются публичные TikTok-видео, TikTok-фотоподборки и Instagram Reels. Фотоподборки уходят одним rich-сообщением: карусель фото плюс блок с треком TikTok (трек включается вручную — API не умеет привязывать звук к карусели); в Docker-образ входит `ffmpeg`, он нужен для склейки звука у видео TikTok. Приватные Instagram-публикации, ролики, для которых Instagram требует login/cookies, и TikTok-посты с пометкой «may not be comfortable for some audiences» не поддерживаются без cookies: экспортируйте cookies из браузера (например, расширением Get cookies.txt) в Netscape-формате и отправьте файл `cookie.txt` боту — он попадёт в volume `ttblow-cache` как `/data/cache/cookies.txt`. Временные файлы создаются в `/tmp` и удаляются после загрузки в Telegram; старые каталоги чистятся при запуске. При ошибке плейсхолдер превращается в сообщение об ошибке: guest-сообщение нельзя ни удалить, ни дополнить вторым ответом. Логи выводятся в stdout; уровень задаётся через `LOG_LEVEL=INFO` или `DEBUG`.
